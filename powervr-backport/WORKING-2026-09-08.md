# The A733's GPU runs on the fully open stack

**2026-09-08.** Kernel driver, firmware, Vulkan and OpenGL — all open source, all
on the hardware.

```
GPU0:
    deviceName   = PowerVR B-Series BXM-4-64 MC1
    deviceType   = PHYSICAL_DEVICE_TYPE_INTEGRATED_GPU
    deviceID     = 0x36104183
    driverID     = DRIVER_ID_IMAGINATION_OPEN_SOURCE_MESA
    driverName   = Imagination open-source Mesa driver
    driverInfo   = Mesa 26.1.8
    apiVersion   = 1.2.354
    device extensions: 279
```

```
OpenGL renderer: zink Vulkan 1.2(PowerVR B-Series BXM-4-64 MC1 (IMAGINATION_OPEN_SOURCE_MESA))
```

No DDK. No `/usr/local/lib`. No per-application environment wrapping. Stock
Fedora Mesa talking to an in-tree kernel driver.

## The stack

| layer | what |
|---|---|
| kernel | `drm/imagination` v6.8, backported to the 6.6.98 BSP (46 lines of adaptation) |
| firmware | `rogue_36.56.104.183_v1.fw` from Imagination's staging linux-firmware |
| Vulkan | Mesa 26.1.8 `libvulkan_powervr_mesa.so` |
| OpenGL | zink over that Vulkan |

## Getting here took four findings

**1. The driver backports cheaply.** v6.8 chosen because `pvr_drm.h` is
byte-identical from v6.8 to v6.16, so the oldest driver still satisfies current
Mesa while sitting closest to our 6.6 base. Total hand-written delta: 46 lines
added, 6 removed - five API drifts plus dropping nouveau, whose `drm_gpuva_mgr`
exports collide with `drm_gpuvm`.

**2. The A733 needs two bits of platform glue.** `img,img-rogue` added to
`dt_match`, and a reset deassert in `pvr_probe()` - the BXM DDK deasserts
`reset_bus` from its own power-on path and the in-tree driver has no reset
handling. Unlike the older img-rgx DDK variant, the img-bxm one does *not* poke
PPU power registers, so reset plus clocks is the entire power sequence. The DT
carries both compatibles and appends duplicate `core`/`sys`/`mem` clock phandles
so the DDK's by-name lookups still resolve from the same DTB.

**3. The firmware was never missing.** The BSP's DDK blob is rejected, correctly:
`info_version 2`, `flags 0x80020810` (OPEN_SOURCE clear), fw 24.2 - while the
driver requires info_version 3, the OPEN_SOURCE bit, and major version 1. Those
are two different firmware product lines, not two packagings of one file.

The open-source build for our BVNC has existed since April in Imagination's
staging area:

```
gitlab.freedesktop.org/imagination/linux-firmware   branch powervr
commit 8a58f81, 2026-04-02
16 blobs, where upstream linux-firmware has 3 - including rogue_36.56.104.183_v1.fw
```

That host serves an Anubis bot-check to every HTTP client including its own REST
API. `git clone --branch powervr` walks straight through. That is the only
reason it was findable.

**4. Mesa gates on conformance, not capability.** With the driver loaded, Mesa
still enumerated only llvmpipe. Forcing the ICD produced the actual reason:

```
WARNING: powervr is not a conformant Vulkan implementation for BXM-4-64.
Pass PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1 if you know what you're doing.
```

It had identified the GPU correctly all along. Mesa declares conformance for
BXM-4-64 at BVNC 36.52.104.182 (the TH1520); ours is 36.56.104.183, same GPU
model, different silicon revision. With the override it enumerates and works.

## What is verified

- Driver probes, deasserts reset, powers the GPU, reads BVNC 36.56.104.183 from
  the hardware ID register and builds the firmware filename from it
- `[drm] FW version v1.1 (build 6976702 OS)` - the firmware processor booted
- `[drm] Initialized powervr 1.0.0 20230904 for 1800000.gpu on minor 1`
- `card1` + `/dev/dri/renderD128`
- Vulkan enumerates the real GPU with 279 device extensions
- GL and GLES run through zink on it
- EGL initialises on the **GBM**, Surfaceless and Device platforms
- Zero GPU faults, timeouts, resets or call traces in the kernel log throughout

## What is not verified

- **No benchmark yet.** `glmark2-es2 --off-screen` fails to create a canvas in
  this build - it does the same on software, so that is glmark2, not the GPU.
  Needs a display session to measure.
- **zink reports GLES 2.0**, against the DDK's GLES 3.2. Whether that is a real
  ceiling or a missing Vulkan feature is unknown.
- **Wayland EGL platform** did not initialise - expected with no compositor
  running, but untested with one.
- The Vulkan driver is explicitly non-conformant for this part. Expect bugs.
- Nothing has been run on a desktop session yet.

## What this fixes, in principle

Every structural limit of the DDK, because this is ordinary Mesa:

| DDK limitation | status here |
|---|---|
| no Wayland EGL platform | Mesa has one (untested with a compositor) |
| no GLX, no desktop libGL | Mesa provides both |
| not a glvnd vendor | Mesa is the glvnd vendor |
| no `VK_EXT_robustness2`, so no zink | zink runs |
| per-app `LD_LIBRARY_PATH` + `SDL_VIDEO_X11_FORCE_EGL` wrapping | not needed |

## The other thing that happened today

Hours were lost to what looked like GPU hangs - ssh dying mid-command, scp
stalling, `vulkaninfo` apparently wedging the board. None of it was the GPU.

The DTB built for this test carries the vendor's `tx-delay = <12>`, the value
this project already measured at 72% loss on 300-byte frames and 100% on 1200.
Small commands returned, anything real died. `grep -c` worked; `grep -n` hung.

The fix exists in `patches/0003-board-dts-rgmii-tx-delay.patch`, but it applies
to `allwinner-device/configs/cubie_a7a/linux-6.6/board.dts`, and this build came
from `kernel-6.6/arch/arm64/boot/dts/`. A USB ethernet adapter sidestepped it and
everything above was measured in one clean pass.

**That patch must be folded into any DTB built from the kernel tree.** It is not
optional and it does not look like a network fault when it is missing.

## Reproducing

```
sudo a7a-extlinux default fedora-6.6.98-pvr+
sudo systemctl set-default multi-user.target      # the software desktop thrashes the board
sudo reboot

sudo modprobe --ignore-install powervr
export PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1
vulkaninfo --summary
MESA_LOADER_DRIVER_OVERRIDE=zink eglinfo -B
```
