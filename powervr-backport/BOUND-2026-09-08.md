# The open-source PowerVR driver is bound to the Allwinner A733

**2026-09-08, on hardware.**

```
card0  sunxi-drm
card1  powervr
bound devices under the platform driver:  1800000.gpu
```

`drm/imagination` - Imagination's own open-source kernel driver, backported from
Linux v6.8 onto the 6.6.98 Allwinner BSP - probed, loaded firmware, and created
a DRM device for the BXM-4-64 in the A733. As far as anything published shows,
that had not been done before on this SoC.

## The missing piece was never missing

Earlier today the driver rejected the BSP's DDK firmware:

```
[drm] loaded firmware powervr/rogue_36.56.104.183_v1.fw
[drm] *ERROR* Unsupported fw info version 2
probe of 1800000.gpu failed with error -22
```

That was correct behaviour. The DDK firmware and the open-source firmware are
different builds: ours declared `info_version 2`, `flags 0x80020810`
(OPEN_SOURCE clear) and firmware version 24.2, while the driver requires
`info_version 3`, the OPEN_SOURCE bit, and major version 1.

The conclusion at that point was "Imagination has never published the
open-source firmware for BVNC 36.56.104.183, so this needs an upstream request."

**That was wrong, and finding out cost one web search.**

Imagination keeps a staging area on freedesktop GitLab for firmware that is not
yet in upstream linux-firmware:

```
https://gitlab.freedesktop.org/imagination/linux-firmware   branch: powervr
commit 8a58f81, 2026-04-02, "powervr: update Imagination Rogue firmware images"
```

It carries **sixteen** blobs where upstream linux-firmware carries three:

```
rogue_4.40.2.51_v1.fw      rogue_22.68.54.30_v1.fw    rogue_36.50.54.182_v1.fw
rogue_4.45.2.58_v1.fw      rogue_22.87.104.18_v1.fw   rogue_36.52.104.182_v1.fw
rogue_4.46.6.62_v1.fw      rogue_33.15.11.3_v1.fw     rogue_36.53.104.796_v1.fw
rogue_5.9.1.46_v1.fw       rogue_36.28.21.182_v1.fw   rogue_36.56.104.183_v1.fw   <<<
rogue_15.5.1.64_v1.fw      rogue_36.29.52.182_v1.fw
rogue_22.102.54.38_v1.fw   rogue_22.67.54.30_v1.fw
```

`rogue_36.56.104.183_v1.fw` - our exact silicon. Published since April. It
checks out against every gate the DDK blob failed:

```
info_version   3              (was 2)
bvnc           36.56.104.183  our GPU
flags          0x00000001     OPEN_SOURCE set   (was 0x80020810)
fw_version     1.1 build 6976702                (was 24.2)
sha256         1db1c399c17401d1f79d46c880db81c724d748c784d4639433b076aba2f9c0d2
```

Note the web UI is behind Anubis bot protection and returns a challenge page to
every HTTP client, including the API. **git** works: `git clone --branch powervr`
over https goes straight through, because the smart-http endpoints are not
gated. That is the only reason this was findable.

## Access note

`gitlab.freedesktop.org` cannot be browsed by a normal fetcher. Reach it with
git, not HTTP. Upstream linux-firmware's own web view is also 403 to plain
clients; `kernel.googlesource.com` mirrors it and answers fine.

## What is confirmed

- The driver binds `img,img-rogue` on the A733's `gpu@1800000`
- Clocks resolve via the duplicate `core`/`sys`/`mem` phandles
- The reset deassert added to `pvr_probe()` works
- The GPU powers up: the driver reads BVNC 36.56.104.183 from the ID register
  and builds the firmware filename from it
- The open-source firmware is accepted
- `card1` is created and the platform device is bound

## What is not yet known

The session wedged immediately afterwards, while running `vulkaninfo` - the
first actual GPU work ever submitted through this path. ssh stopped responding;
the board still answers ping, so the kernel is alive but userspace is stuck.

So: **the driver binds. Whether it renders is untested.** Nothing here claims
working acceleration yet.

Reproducing needs the console, which is where this was left.

## Reproducing

1. Boot `fedora-6.6.98-pvr+` (text mode - `systemctl set-default
   multi-user.target` first; on a graphical boot the software-rendered desktop
   thrashes the board badly enough to break file transfers)
2. `sudo modprobe --ignore-install powervr`
3. `ls -l /sys/class/drm/`

Do not run `vulkaninfo` until the hang is understood.
